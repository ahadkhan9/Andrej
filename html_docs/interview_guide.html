13. LLM Interview Preparation Guide

This guide compiles common interview questions and demonstrates how answer quality scales across Junior, Mid-level, and Senior engineering levels.

Question 1: Explain the purpose of weight tying in transformers.

Junior Level Answer:

"Weight tying is used to share parameters between the input embeddings and output projection layer, saving memory."

Mid-level Level Answer:

"We share weights between the token embedding matrix (wte) and output linear head (lm_head). Since they share dimensions ($V \times C$), we tie them. This reduces parameter counts by about 19.3M parameters and reduces memory footprint during training, while enforcing semantic matching between token inputs and prediction outputs."

Senior Level Answer:

"Weight tying shares the weights of the input projection $X \cdot W_{emb}^T$ and output logit classification $H \cdot W_{head}$. We enforce $W_{head} = W_{emb}$. This acts as a regularizer, forcing semantic vectors in the embedding space to directly align with the prediction log-likelihood coordinates. During backpropagation, gradients from both lookup operations accumulate into the same physical weight tensor, which is then updated by the optimizer. This saves memory (specifically, $V \times C \times 4\text{ bytes}$ for weights, plus gradients and optimizer states) and improves convergence rate on smaller vocabularies."

Question 2: Why do we normalize micro-batch loss during gradient accumulation?

Junior Level Answer:

"We divide the loss by the number of accumulation steps so that the final gradient update step has the correct size."

Mid-level Level Answer:

"PyTorch loss functions compute the average loss over the batch. If we accumulate gradients over $N$ steps, the gradients sum up. Without normalization, the final gradient step would be $N$ times larger. Dividing each micro-batch loss by $N$ before calling backward normalizes the gradients, matching the step size of a single large batch."

Senior Level Answer:

"Mathematically, the gradient of the average loss over a batch $D$ partitioned into $N$ micro-batches $d_i$ is: $$\nabla \mathcal{L}(D) = \frac{1}{N} \sum_{i=1}^N \nabla \mathcal{L}(d_i)$$ Because PyTorch's `.backward()` accumulates gradients additively: $$\text{accumulated\_grad} = \sum_{i=1}^N \nabla \mathcal{L}(d_i)$$ We must scale each micro-batch loss by $1/N$ beforehand to ensure the final sum matches the true average gradient. Failing to normalize is equivalent to scaling the learning rate by $N$, which typically destabilizes training and causes the loss to explode."

Question 3: How does FlashAttention optimize the self-attention bottleneck?

Junior Level Answer:

"FlashAttention makes self-attention faster and use less memory by running on the GPU."

Mid-level Level Answer:

"Standard attention stores the intermediate $(T, T)$ attention score matrix in High Bandwidth Memory (HBM), which scales quadratically ($O(T^2)$). FlashAttention tiles the inputs to run attention calculations entirely in the GPU's fast, on-chip SRAM cache, reducing memory bandwidth bottlenecks and speeding up execution."

Senior Level Answer:

"Self-attention is typically memory-bandwidth-bound rather than compute-bound. FlashAttention reorganizes the attention computation by tiling the input matrices $Q, K, V$ into blocks that fit within the GPU's fast, on-chip SRAM cache. It computes attention incrementally using online softmax normalization, writing only the final output matrix of shape $(B, T, C)$ back to HBM. This reduces HBM memory access from $O(T^2)$ to $O(T)$, converting attention from a memory-bandwidth-bound operation to a compute-bound operation. During the backward pass, FlashAttention recomputes the intermediate attention matrix on-the-fly using stored SRAM blocks, eliminating the need to store the massive forward attention matrix in memory."
