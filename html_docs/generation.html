05. Next-Token Prediction & Generation

00. Overview → 01. BPE Parsing → 02. Embeddings → 03. Attention → 04. Pipelines → 05. Generation

The Token's Journey

Our token has navigated all 6 transformer blocks, picking up contextual properties. We now arrive at the model's output gate, where the mathematical features are translated back into a token prediction.

  1. Final LayerNorm (ln_f): Standardizes the output features of the residual stream one last time.
  2. Language Modeling Head (lm_head): Projects the normalized vector of shape [B, T, C] up to shape [B, T, V] (where $V=50257$). These raw, unscaled output scores are called logits.
  3. Logit Selection: We slice the logits to retrieve the scores for the final sequence token (index $-1$), scaling the values by a temperature factor.
  4. Top-K Filtering & Softmax: We retain only the $K$ highest logits, zero out the rest to $-\infty$, and apply Softmax to convert the scores into a probability distribution.
  5. Sampling & Appending: A multinomial sampler picks the next token ID (e.g. 382 for " determined"). We append this new ID to our context queue, shift the context window, and feed it back into the loop.
flowchart TD BlockOut["Final Block Output: [B, T, C]"] -->|ln_f LayerNorm| Norm["Normalized State: [B, T, C]"] Norm -->|Linear lm_head| Logits["All Logits: [B, T, V]"] Logits -->|Slice index -1| LastLogit["Last Token Logits: [B, V]"] LastLogit -->|Divide by Temperature| ScaledLogits["Scaled Logits: [B, V]"] ScaledLogits -->|Top-K Crop| CroppedLogits["Cropped Logits: [B, V]"] CroppedLogits -->|Softmax| Probs["Probabilities: [B, V]"] Probs -->|Multinomial Sample| NextID["Next Token ID: [B, 1]"] NextID -->|Concatenate| Append["Append to Context: [B, T+1]"]

Backend Engineer Lens: Streaming Buffers

In backend engineering, autoregressive text generation is structured like an **incremental queue/buffer append loop** (similar to pushing events to an HTTP Server-Sent Events (SSE) stream).

  • Logits → Priority Values: Think of logits as raw, unnormalized priority metrics. They represent raw voting counts for each item in the token database.
  • Temperature → Load Balancing: High temperature acts like round-robin load balancing, spreading traffic across less optimal routes (creating creative, diverse outputs). Low temperature acts like rigid failover routing, forwarding all requests exclusively to the primary node with the highest score (greedy deterministic outputs).
  • Generation Loop → Buffer Writing: We read the current context window buffer, calculate the next index, write the index to our buffer queue, and stream the parsed word token back to the client immediately before repeating.

Production Relevance

  • Time-to-First-Token (TTFT) vs Inter-Token Latency: Generating text token-by-token is slow because each step must reload all model parameters to project the new logit. This makes generation **memory-bandwidth bound**. In serving frameworks (vLLM, Hugging Face TGI), we stream each token to the client as it is sampled using SSE events, minimizing TTFT and improving user perceived latency.
  • Speculative Decoding: To bypass memory loading bottlenecks, speculative decoding runs a fast, lightweight "draft model" (e.g. 1B parameters) to generate 5-10 draft tokens in a row. The large "target model" (e.g. 70B parameters) evaluates all draft tokens in parallel in a **single forward pass**, accepting or rejecting them. This yields up to a 2x inference speedup without altering output mathematics.

Verification

We test our generation loop by running text generation using pre-trained GPT-2 (124M) weights on our custom architecture. Run the command below to witness readable English output:

python3 generate.py --prompt "Alan Turing determined that" --max_tokens 30

Common Interview Followups

What is the mathematical role of Temperature in generation? Show the equations.

Temperature $T$ scales the logits before applying the Softmax function: $$P(x_i) = \frac{e^{z_i / T}}{\sum_j e^{z_j / T}}$$ Where $z_i$ is the raw logit score for token $i$.

  • Low Temperature ($T \to 0$): Logit differences are amplified. The probability of the highest logit approaches 1.0, while all other probabilities drop to 0, resulting in deterministic greedy selection.
  • High Temperature ($T \to \infty$): Logit differences are compressed towards 0. The terms $z_i / T$ approach 0, so $e^0 = 1$. The probabilities converge to a uniform distribution, producing high-entropy, random text.

What is the difference between Top-K and Top-P (nucleus) sampling?

  • Top-K: Restricts sampling to a static number ($K$) of highest-probability tokens. While fast, if $K=50$ and only 2 tokens are relevant, the model is forced to sample from 48 noise tokens.
  • Top-P (Nucleus): Restricts sampling dynamically to the smallest set of tokens whose cumulative probability sum exceeds threshold $P$ (e.g. $P=0.90$). If the model is confident, the candidate pool might shrink to 2 tokens; if the model is confused, the pool expands to 100 tokens, yielding higher coherence.

Why must we crop the input context window before passing it to the model during generation?

In our model configuration, the positional embedding matrix wpe has a fixed size of block_size=256 (or 1024 for official GPT-2). If a sequence length exceeds this capacity, accessing wpe throws an index out-of-bounds error. To prevent this, the code crops the context window to the last block_size tokens: 

idx_cond = idx[:, -self.config.block_size:]
This implements a sliding-window buffer, discarding historical tokens beyond capacity limits.
