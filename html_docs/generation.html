08. Generation: Autoregressive Decoding

Why should I care?

Generating text from an LLM is a dynamic process. Adjusting decoding parameters (like temperature and top-k) determines whether the model's outputs are deterministic, creative, repetitive, or nonsensical. Understanding these sampling algorithms is essential for tuning generation behavior to fit specific use cases (such as creative writing vs. code generation).

Level 1 — Intuition & Mental Model

Imagine you are a writer picking the next word in a story. You look at the sentence you have written so far, and list possible next words with their likelihoods.

To write the next sentence, you use a few rules:

  • Greedy Selection (Argmax): Always pick the single most probable word. This often leads to repetitive and boring sentences.
  • Temperature: Control how willing you are to choose less likely words. A low temperature makes you stick strictly to safe, highly probable words, while a high temperature encourages you to pick more creative, unusual words.
  • Top-k Filtering: Throw out the bottom portion of your word list. This ensures you never pick a completely irrelevant word from the tail of the distribution.

Level 2 — Engineering View

In model.py:L327-L370, the generate function coordinates this process. Because the position embedding matrix (wpe) has a fixed context length of block_size (256), the model cannot accept sequences longer than 256. We crop the context window before passing it to the forward pass:

# From model.py:L348
idx_cond = idx[:, -self.config.block_size:]

We scale the raw outputs (logits) by the temperature parameter: 

# From model.py:L354
logits = logits[:, -1, :] / temperature
We then apply top-k filtering, setting all logits below the top-k threshold to $-\infty$ so they receive a probability of 0: 
# From model.py:L357-L359
if top_k is not None:
    v, _ = torch.topk(logits, min(top_k, logits.size(-1)))
    logits[logits < v[:, [-1]]] = -float('Inf')
Finally, we convert these filtered logits to a probability distribution using softmax and sample a token ID using torch.multinomial:

probs = F.softmax(logits, dim=-1)
idx_next = torch.multinomial(probs, num_samples=1)
idx = torch.cat((idx, idx_next), dim=1)

3. Mathematical View

Temperature scaling modifies the softmax probability distribution: $$P(x_i) = \frac{e^{z_i / T}}{\sum_j e^{z_j / T}}$$ Where $z_i$ represents the raw logit score for token $i$, and $T$ is the temperature.

  • As $T \to 0$, the probability of the most likely token approaches 1, matching greedy decoding (argmax).
  • As $T \to \infty$, the probability distribution becomes uniform, making token selection completely random.

4. What happens if we remove top-k filtering?

If we remove top-k filtering (and keep temperature $T = 1.0$ or higher):

  • The model will occasionally sample low-probability tokens from the long tail of the vocabulary distribution.
  • Once an incorrect or nonsensical token is generated, it becomes part of the context for subsequent predictions, causing errors to compound.
  • This typically causes the generated text to quickly devolve into gibberish or spelling errors.
