15. From GPT-2 to Modern AI Systems

The Token's Journey

Reproducing a base transformer model like GPT-2 is the foundation of LLM engineering. However, in modern production architectures (e.g. Llama 3, Mistral, Gemini), the token flows through refined structural gates (RoPE, RMSNorm, GQA) and operates within a layered enterprise system stack (Fine-Tuning, Serving, RAG, and Agents).

Backend Engineer Lens: Architecture Evolution & Serving Layers

Think of this codebase as a **raw database storage engine**. You understand how it writes parameters to disk (checkpointing) and retrieves indexes (attention). But in production, you don't expose raw storage layers directly to users. You wrap the database in an ORM (PEFT/LoRA), place it behind an API Gateway proxy (inference servers like vLLM), cache context requests (RAG), and script automation workflows (Agents).

Normalization Placement Pre-LayerNorm (before block layers) Pre-RMSNorm Removes mean calculations, speeding up GPU runtime by 10-50%.
Attention Design Multi-Head Attention (MHA) Grouped-Query Attention (GQA) Reduces KV Cache RAM usage by sharing Key/Value heads across groups.

The Production Stack Mapping

1. PagedAttention & Serving (vLLM)

  • This Repository: Standard Multi-Head Attention dot products in model.py:CausalSelfAttention.
  • Production Equivalent: **vLLM** serving engines. Sharing KV states (KV Cache) in GPU memory is critical to handle multiple concurrent clients. vLLM uses virtual memory paging concepts (PagedAttention) to prevent fragmentation, allowing a 10x throughput speedup during high-concurrency API calls.

2. Adapter Fine-Tuning (LoRA / QLoRA)

  • This Repository: Full parameter backpropagation updating every single weight in train.py.
  • Production Equivalent: Parameter-Efficient Fine-Tuning (**PEFT**) using **LoRA** (Low-Rank Adaptation). Base weights are frozen (read-only), and tiny sidecar projection weights are trained. **QLoRA** quantizes base weights to 4-bit, allowing fine-tuning on consumer-grade hardware.

3. RAG & Vector Search Databases

  • This Repository: Local tiktoken subword encoding in data.py:DataLoaderLite.
  • Production Equivalent: Retrieval-Augmented Generation (**RAG**). In production, context is dynamically injected. Unstructured document payloads are split, converted into embedding vectors, and stored in vector databases (e.g. pgvector, Pinecone). When a query arrives, we perform a vector similarity search, retrieve matching records, and paste them into the LLM context.

Common Interview Followups

Why do modern LLMs use Grouped-Query Attention (GQA) instead of standard Multi-Head Attention (MHA)?

In Multi-Head Attention, every Query head has a corresponding Key and Value head. During autoregressive generation, we cache all Key and Value tensors in memory (KV Cache). At large batch sizes and long context lengths, this KV Cache consumes massive GPU RAM, limiting throughput. **Grouped-Query Attention** (GQA) groups Query heads (e.g., 8 Query heads per group) and shares a single Key and Value head pair across each group. This reduces the memory footprint of the KV Cache by up to 8x, allowing significantly larger serving batch sizes and longer context windows while maintaining near-identical model accuracy.

What is SwiGLU Gated Activation, and why is it preferred over GELU?

SwiGLU is a Gated Linear Unit activation function defined as: $$\text{SwiGLU}(x) = (\text{Swish}(x W) \otimes x V)$$ Where $W$ and $V$ are projection weight matrices, and $\otimes$ is element-wise multiplication. Unlike standard GELU which simply applies a static non-linear threshold to a single projection output, SwiGLU uses a gating mechanism where one projection ($x W$) dynamically scales the activations of a secondary projection ($x V$). This gating structure increases representational capacity, allowing the network to learn complex logical relationships more efficiently than standard GELU networks.
