07. Optimization: Apple Silicon & Compilers

Why should I care?

Training transformers is highly compute-intensive. Without hardware and compiler optimizations, training even a small model can take hours or days. Understanding memory bandwidth, mixed-precision arithmetic, and GPU execution queues allows you to maximize throughput and make full use of local hardware resources (like Apple Silicon GPU cores).

Level 1 — Intuition & Mental Model

Imagine a kitchen where a chef is preparing complex dishes. In standard eager mode, the chef walks to the refrigerator, grabs one ingredient, walks back to the counter, chops it, walks back to the refrigerator for the next ingredient, and so on. This constant back-and-forth is slow.

To optimize this process:

  • Kernel Fusion (torch.compile): Plan ahead and bring all necessary ingredients to the counter at once, completing multiple steps in place before returning anything to the refrigerator.
  • Mixed Precision (AMP): Package ingredients in smaller containers (float16 instead of float32) so the chef can carry twice as much in each trip.
  • FlashAttention: Keep the most frequently used ingredients in a small basket right next to the cutting board (fast SRAM cache) instead of walking to the pantry (High Bandwidth Memory) every time.

Level 2 — Engineering View: "Why is this faster?"

We trace performance improvements by analyzing how specific bottlenecks are resolved:

  • CPU vs. GPU: The CPU executes instructions sequentially on a few powerful cores. The GPU (or MPS backend) contains thousands of smaller cores designed to perform simple arithmetic operations (like matrix multiplications) in parallel, providing an immediate speedup.
  • FP32 vs. FP16 (AMP): FP32 uses 4 bytes per number, while FP16 uses 2 bytes. Moving to FP16 halves the amount of data transferred between memory and the GPU cores, resolving memory bandwidth bottlenecks and nearly doubling throughput.
  • FlashAttention: Standard attention writes the intermediate $(T, T)$ score matrix to High Bandwidth Memory (HBM) and reads it back multiple times. FlashAttention tiles the inputs to run attention calculations entirely in the GPU's fast, on-chip SRAM cache, reducing slow memory access from $O(T^2)$ to $O(T)$.
  • Graph Compilation (torch.compile): Standard eager mode executes PyTorch operations one-by-one, introducing overhead. torch.compile fuses adjacent operations (e.g. LayerNorm + Bias Add + Activation) into a single compiled kernel, keeping activations on-chip instead of round-tripping them to HBM.

3. Mathematical View

Compiler graph tracing models the execution path as a Directed Acyclic Graph (DAG) of operations: $$\mathcal{G} = (\mathcal{V}, \mathcal{E})$$ Where $\mathcal{V}$ represents operation kernels (e.g., Matrix Multiply, Add, Softmax) and $\mathcal{E}$ represents tensor data dependencies. The compiler optimizes this graph by merging adjacent nodes to minimize data transfers, ensuring the GPU spends its time performing computations rather than waiting for memory transfers.
