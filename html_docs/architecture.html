01. Architecture: Token-to-Loss Lifecycle

Why should I care?

An LLM is a complex mathematical pipeline. When you scale up training across thousands of GPUs, or deploy a model to run on edge devices, you must be able to track every single tensor dimension and state modification. If you cannot trace the exact shapes, parameter counts, and memory layout at every line of code, you cannot debug shape mismatch errors, optimize memory allocations, or calculate the hardware limits of your training infrastructure.

Level 1 — Intuition & Mental Model

Think of the transformer architecture as a factory production line. Raw materials (text characters) enter at the front, get processed, packaged, and stamped with predictions at the end.

The core layout consists of three primary zones:

  • The Loading Dock (Embeddings): Raw text characters are translated into numerical tokens, which are then mapped to continuous embedding vectors. Positional embeddings are added to provide spatial context.
  • The Assembly Line (Transformer Blocks): The vectors pass sequentially through multiple blocks. In each block, self-attention mixes information between tokens, while the MLP extracts features from each token individually.
  • The Packaging Station (Head & Loss): The vectors are mapped back to vocabulary scores (logits) to predict the next token. During training, the cross-entropy loss measures the difference between these predictions and the target tokens.

Detailed Shape Stages:

  • Input Tensors: idx is a 2D integer tensor of shape [B, T] ($4 \times 256$).
  • Token Embeddings: wte(idx) maps each integer token to a dense representation, returning shape [B, T, C] ($4 \times 256 \times 384$).
  • Position Embeddings: wpe(pos) maps sequence positions to vectors of shape [T, C] ($256 \times 384$). When added to the token embeddings, PyTorch broadcasts the positional vectors across the batch dimension, returning a summed tensor of shape [B, T, C].
  • Transformer Blocks: The hidden state maintains the shape [B, T, C] through all 6 blocks, ensuring compatibility with residual connections.
  • Final Logits: The final linear layer (lm_head) maps each token vector from dimension $C$ to the vocabulary size $V$, returning a tensor of shape [B, T, V] ($4 \times 256 \times 50257$).

3. Mathematical View

Each block update can be written as: $$x^{(l)} = x^{(l-1)} + \text{Attention}(\text{LayerNorm}(x^{(l-1)}))$$ $$x^{(l)} = x^{(l)} + \text{MLP}(\text{LayerNorm}(x^{(l)}))$$ The final classification score (logits) for a target token at index $t$ is: $$z_t = W_{tie} \cdot \text{LayerNorm}(x_t^{(L)})$$ Where $W_{tie}$ is the shared weight tensor of shape $(V, C)$ used for both the input embeddings and output projection.

4. What happens if we remove residual connections?

If we remove the residual connections (i.e., updating states as $x_{l+1} = f(x_l)$ rather than $x_{l+1} = x_l + f(x_l)$), the model fails to train entirely. Mathematically, the derivative of the output with respect to the input through $L$ residual layers is: $$\frac{\partial x_L}{\partial x_0} = I + \sum_{l=1}^L \frac{\partial f_l(x_{l-1})}{\partial x_0}$$ This addition of the identity matrix $I$ ensures that gradients can propagate back to early layers without being scaled down. Without the identity path, gradients must flow back through a chain of multiplications of weights and non-linearities: $$\frac{\partial x_L}{\partial x_0} = \prod_{l=1}^L \frac{\partial f_l(x_{l-1})}{\partial x_{l-1}}$$ If the weight values are small ($< 1.0$), gradients vanish to zero. If they are large ($> 1.0$), gradients explode, causing the model to return NaN within the first few steps.

5. Build Intuition through Numbers: Parameter Sizing

Let's calculate the exact parameter count for our custom model config:

  • Embeddings:
    • wte: $50257 \times 384 = 19,298,688$ parameters.
    • wpe: $256 \times 384 = 98,304$ parameters.
  • Layers per Block (x6 Blocks):
    • ln_1 and ln_2: $2 \times (384 \text{ weights} + 384 \text{ biases}) = 1,536$ parameters.
    • c_attn: $(384 \times 1152) \text{ weights} + 1152 \text{ biases} = 443,520$ parameters.
    • c_proj (attention output): $(384 \times 384) \text{ weights} + 384 \text{ biases} = 147,840$ parameters.
    • c_fc (MLP expand): $(384 \times 1536) \text{ weights} + 1536 \text{ biases} = 591,360$ parameters.
    • c_proj (MLP contract): $(1536 \times 384) \text{ weights} + 384 \text{ biases} = 590,208$ parameters.
    • Block total: $1,536 + 443,520 + 147,840 + 591,360 + 590,208 = 1,774,464$ parameters.
  • Total Non-Embedding parameters: $$6 \times 1,774,464 \text{ (Blocks)} + 768 \text{ (ln\_f)} = \mathbf{10,745,856 \text{ parameters}}$$
