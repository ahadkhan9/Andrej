12. The Tensor Shape Journey

Why should I care?

In deep learning, shape mismatch errors are the most common source of runtime crashes. Because PyTorch relies on dynamic graph execution, a single incorrect transpose, squeeze, or dimension broadcast will cause your matrix multiplications to fail. Tracing the exact shape transformations through each layer of the model is essential for debugging and writing custom network architectures.

Backend Engineer Lens

Think of tensor shapes as type definitions in a data pipeline. If you pass a JSON object of type {id: int, name: str} to a service that expects a list of items [{id: int}], the schema validation fails. Similarly, tensor shapes define the API contract between layers: the output dimensions of one layer must align with the input expectations of the next.

The Shape Journey ($B=4, T=256, C=384, V=50257, H=6$)

flowchart TD Step1["Input IDs: [B, T]"] -->|wte lookup| Step2["Token Embeds: [B, T, C]"] Step1 -->|wpe lookup| Step3["Position Embeds: [T, C]"] Step2 & Step3 -->|Sum (Broadcast)| Step4["Summed Embeds: [B, T, C]"] Step4 -->|Attention Projections| Step5["QKV Projection: [B, T, 3C]"] Step5 -->|Head Split| Step6["Q, K, V Heads: [B, H, T, D]"] Step6 -->|Softmax Dot Product| Step7["Attention Context: [B, T, C]"] Step7 -->|MLP Expansion| Step8["MLP Inner: [B, T, 4C]"] Step8 -->|MLP Contraction| Step9["MLP Output: [B, T, C]"] Step9 -->|LM Head Projection| Step10["Logits: [B, T, V]"] Step10 & Targets["Targets: [B, T]"] -->|Cross Entropy| Step11["Loss: Scalar []"]

1. Input Tokens (idx)

  • Shape: [4, 256] representing [B, T].
  • Why it has this shape: Contains 4 batch sequences, each containing 256 token IDs.
  • Common bugs: Passing floats instead of integers, or sequences longer than block_size.

2. Embeddings Sum (tok_emb + pos_emb)

  • Input Shapes: tok_emb: [4, 256, 384]; pos_emb: [256, 384].
  • Output Shape: [4, 256, 384].
  • Why it changes: PyTorch automatically broadcasts the positional embeddings across the batch dimension (duplicating them 4 times) during element-wise addition.
  • Common bugs: Embedding dimensions not matching, causing addition to fail.

3. Attention Projections (c_attn)

  • Input Shape: [4, 256, 384].
  • Output Shape: [4, 256, 1152] representing [B, T, 3C].
  • Why it changes: The input is projected from dimension $C \to 3C$ to generate Query, Key, and Value vectors.

4. Multi-Head Split

  • Input Shape: [4, 256, 1152].
  • Output Shape: [4, 6, 256, 64] representing [B, H, T, D].
  • Why it changes: The embedding dimension $C=384$ is split across $H=6$ attention heads, giving a head dimension of $D=64$.
  • Common bugs: Reshaping dimensions in the wrong order. Always verify your transpositions: 
    # Correct reshaping:
x.view(B, T, H, D).transpose(1, 2)  # Output shape: [B, H, T, D]

5. Attention Logits (Q @ K.T)

  • Input Shape: $Q, K$: [4, 6, 256, 64].
  • Output Shape: [4, 6, 256, 256] representing [B, H, T, T].
  • Why it changes: Multiplying queries by keys computes the similarity score between every token and all other tokens in the sequence.

6. LM Head Logits (lm_head)

  • Input Shape: [4, 256, 384].
  • Output Shape: [4, 256, 50257] representing [B, T, V].
  • Why it changes: Projects normalized token vectors back to the vocabulary space.

7. Loss calculation

  • Input Shape: Logits: [1024, 50257]; Targets: [1024] (both flattened).
  • Output Shape: Scalar [].
  • Why it changes: Cross-entropy loss averages the prediction errors across all tokens, returning a single scalar value.
