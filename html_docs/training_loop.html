06. Training Loop: Mechanics & Schedule

Why should I care?

The training loop controls how the model learns from data. Understanding the mechanics of gradient accumulation, learning rate scheduling, and weight decay is essential for stabilizing training and preventing issues like exploding gradients or stuck loss curves. Configuring these parameters correctly is critical for ensuring the model converges efficiently.

Level 1 — Intuition & Mental Model

Imagine you are guiding a hiker down a foggy mountain to find the lowest valley (the lowest loss). If you take steps that are too large, you might overshoot the valley and end up on another peak. If you take steps that are too small, the journey will take forever.

To guide the hiker effectively, we use a few strategies:

  • Warmup: Start with small, cautious steps (low learning rate) until the hiker gets their bearings, then increase step size.
  • Cosine Decay: As the hiker gets closer to the valley floor, gradually reduce the step size to avoid overshooting.
  • Gradient Accumulation: Instead of asking the hiker to make a decision after every step, let them take a few steps, average their path, and then make a correction.
  • Gradient Clipping: If the hiker starts sliding down a steep cliff (exploding gradient), pull them back to prevent a crash.

Level 2 — Engineering View: What is happening in memory?

Let's estimate the GPU/MPS memory requirements during a training step for our configuration ($30\text{M}$ parameters, $B=4$, $T=256$):

Memory Element Calculation / Value Tracking Estimated Size
Model Parameters $30\text{M}$ weights stored in float32 (4 bytes per param) ~120 MB
Gradients $30\text{M}$ gradients stored in float32 (4 bytes per param) ~120 MB
Optimizer States AdamW tracks 2 moments (mean/variance) per weight in float32 (8 bytes per param) ~240 MB
Activations Intermediate activations saved during the forward pass for backpropagation. Scales with layer count and batch size. ~180 MB
Total Training Memory Sum of weights, gradients, optimizer states, and activations ~660 MB

3. Mathematical View

During gradient accumulation over $N$ steps, the total gradient update is the average of the gradients of the micro-batches: $$\nabla \mathcal{L}(D) = \frac{1}{N} \sum_{i=1}^N \nabla \mathcal{L}(d_i)$$ This is why we scale each micro-batch loss by $N$ (grad_accum_steps) before calling backpropagation: $$\mathcal{L}_{scaled} = \frac{\mathcal{L}(d_i)}{N}$$ $$\nabla \mathcal{L}_{scaled} = \frac{\nabla \mathcal{L}(d_i)}{N}$$ When PyTorch accumulates these scaled gradients over $N$ steps, the final sum matches the true average gradient of the entire batch.

4. What happens if we remove gradient clipping?

If we remove gradient clipping (nn.utils.clip_grad_norm_(model.parameters(), 1.0)):

  • If the model encounters a steep region of the loss landscape (common when training deep transformers), the gradient values can grow extremely large.
  • Without clipping, the optimizer will take a massive step, shifting model weights to extreme values.
  • This typically destabilizes the model, causing activations to overflow and the loss function to return NaN, halting training.
