03. Attention: The Context Index

00. Overview → 01. BPE Parsing → 02. Embeddings → 03. Attention → 04. Pipelines → 05. Generation

The Token's Journey

Our token is currently represented as a vector $x$ containing positional and word embedding values. However, it exists in isolation—it has no knowledge of the surrounding tokens in the sentence.

  1. Projections (Q, K, V): "The Token" projects itself into three distinct query-ready roles using linear weights:
    • Query (Q): "What attributes am I searching for in other tokens?"
    • Key (K): "What attributes do I possess that other tokens might look for?"
    • Value (V): "What semantic content do I actually hold?"
  2. Similarity Dot Product ($Q \cdot K^T$): The Query vector of "The Token" is multiplied with the Key vectors of all previous tokens to evaluate similarity.
  3. Causal Masking: To keep generation chronological, "The Token" is masked from looking at future tokens' Keys. Future positions are set to $-\infty$, resulting in zero attention weight after softmax.
  4. Value Aggregation ($W \cdot V$): Normalized attention scores are used to calculate a weighted sum of the Value vectors of all previous tokens, creating a contextualized feature output.

Backend Engineer Lens: Similarity Search

Think of self-attention as a distributed vector similarity search query against an in-memory database.

  • Query (Q) → Search term payload: The search parameters passed in by the client (e.g. "author of Turing machine").
  • Key (K) → Database primary index keys: The index metadata fields associated with records (e.g. "inventor", "year", "concept").
  • Value (V) → Database payload records: The actual records containing the data fields (e.g. {"name": "Alan Turing", "work": "Computers"}).

Mathematically, we execute: $$A = \text{Softmax}\left( \frac{Q K^T}{\sqrt{d_k}} + M \right) V$$

The dot product $Q K^T$ measures similarity between the query term and all index keys. The causal mask $M$ acts like a SQL WHERE index_id <= current_id constraint, blocking access to records that have not been written to the table yet. Softmax normalizes the scores to a sum of 1.0, and the final multiplication gathers the record payloads weighted by their match relevance.

FlashAttention is a system optimization. In backend terms, it is like refactoring an algorithm to avoid slow disk read/writes by performing cache-local blocking, shifting execution from memory-bandwidth bound to compute bound.

Production Relevance

  • KV Caching: Autoregressive text generation produces one token at a time. Re-running the attention math over all historic tokens at every step scales quadratically ($O(T^2)$). Instead, production servers cache the computed Key ($K$) and Value ($V$) tensors of all past steps in memory (the KV Cache), performing a simple append at the new step and reducing context retrieval complexity to $O(T)$.
  • PagedAttention (vLLM): The KV Cache consumes massive RAM, leading to fragmentation (like disk fragmentation). vLLM introduces virtual memory paging concepts (similar to operating system pages) to allocate blocks of KV caches dynamically in GPU memory, allowing higher batch sizes and concurrency.

Verification

Our logit parity verification test in generate.py validates the math: when loading pre-trained weights, our custom implementation matches Hugging Face's logits with a maximum absolute difference under $10^{-5}$ across multiple prompts, proving that causal masking and FlashAttention bindings are mathematically aligned.

Common Interview Followups

Why is attention complexity $O(T^2)$? Can you explain the math?

In self-attention, we calculate attention scores between every token and all other tokens. Given a sequence of length $T$, we multiply a Query matrix $Q \in \mathbb{R}^{T \times D}$ by the transpose of the Key matrix $K \in \mathbb{R}^{T \times D}$. The resulting matrix multiplication $Q K^T$ yields a score matrix of size $T \times T$. Computing this matrix requires $T^2 \times D$ floating-point multiplications, which scales quadratically with sequence length $T$. This makes long-context inputs (e.g. 32k or 128k context) extremely expensive in terms of both GPU memory storage and computation time.

How does FlashAttention optimize self-attention without changing the mathematical output?

Standard attention writes the large intermediate $T \times T$ attention matrix to High-Bandwidth GPU memory (HBM), then reads it back to calculate softmax, and reads it again to multiply by $V$. This HBM read/write loop is a memory-bandwidth bottleneck. FlashAttention uses tiling. It loads small block chunks of $Q$, $K$, and $V$ into the GPU's fast, on-chip local SRAM memory. It computes attention scores, updates the softmax scaling factor incrementally using online softmax calculations, and computes the final output weighted values locally in SRAM. It only writes the final output tensor back to HBM, reducing memory access overheads and yielding up to a 3-4x speedup.
