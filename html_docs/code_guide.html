16. Code Reading Guide

Why should I care?

Navigating a new codebase can be overwhelming. Understanding the architecture of the repository—how files interact, where key components are implemented, and the optimal order to read them—is essential for building mental models and extending the codebase with new features.

Backend Engineer Lens

Think of reading this ML codebase like onboarding to a new backend project. Instead of trying to understand every service simultaneously, you trace a request: starting at the routing layer (the data pipeline), following it through the controllers (the model layers), and observing how it is saved to the database (the checkpoints).

Recommended Reading Order

1. data.py (The Data Ingestion Layer)

  • Why it exists: Handles subword tokenization and yields batches of inputs and targets.
  • Focus on: The sliding window math: buf[:-1] for inputs, and buf[1:] for targets.
  • Interview takeaways: How data preparation prevents target leakage.

2. model.py (The Core Architecture)

  • Why it exists: Contains the structural layers of the GPT model (Embeddings, Causal Attention, MLP, Transformer Block).
  • Focus on: Head splitting transpositions, causal masking, weight tying, and initialization scaling.
  • Interview takeaways: Pre-LN gradient flow, and $O(T^2)$ attention complexity.

3. train.py (The Control Loop)

  • Why it exists: Manages optimizer steps, learning rate scheduling, gradient accumulation, and checkpoints.
  • Focus on: AdamW weight decay groups, gradient accumulation math, and learning rate schedules.
  • Interview takeaways: Gradient clipping and mixed precision training.

4. generate.py & hellaswag.py (Verification & Evaluation)

  • Why they exist: generate.py verifies model correctness using logit parity checks. hellaswag.py runs validation benchmark evaluations.
  • Focus on: Temperature scaling, top-k filtering, and completion token log-likelihood alignment.
