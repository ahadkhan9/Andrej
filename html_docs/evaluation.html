10. Evaluation: Validation & Downstream Benchmarks

Why should I care?

Training loss only tells you how well the model is fitting the training data, not how well it generalizes to new text or performs on reasoning tasks. By evaluating the model on validation splits and reasoning benchmarks (such as HellaSwag), we can track validation loss trends and measure its common-sense understanding, preventing overfitting.

Level 1 — Intuition & Mental Model

Imagine you are preparing a student for a final exam. If you only give them the practice questions they have already studied, they will memorize the answers without understanding the underlying concepts (overfitting).

To measure their actual understanding:

  • Validation Split: Give the student a set of test questions they have never seen before (validation split) to evaluate their generalization.
  • Downstream Benchmark (HellaSwag): Give them a multiple-choice common-sense exam to test their reasoning, rather than their ability to memorize text.

Level 2 — Engineering View

In hellaswag.py:L121-L136, we evaluate completion options. We concatenate the prompt context and each completion option, and run a forward pass to calculate logits. We then isolate the completion token predictions, compute the log-softmax across the vocabulary dimension, and average the probabilities of the actual target completion tokens:

# Slice logits and targets to align only with the completion tokens
logits_ending = logits[0, num_ctx - 1:]
targets_ending = y[0, num_ctx - 1:]

# Log probabilities (log_softmax)
log_probs = F.log_softmax(logits_ending, dim=-1)

# Gather log probs for the target tokens
target_log_probs = log_probs[torch.arange(len(targets_ending)), targets_ending]

# Average log probability for the option
mean_log_prob = target_log_probs.mean().item()

The completion option that yields the highest average log-likelihood (least negative loss) is chosen as the model's prediction.

3. Mathematical View

Given the sequence of $K$ completion target tokens $c = (c_1, \dots, c_K)$, the average log-likelihood is: $$\text{LL} = \frac{1}{K} \sum_{i=1}^K \ln P(c_i \mid \text{context}, c_1, \dots, c_{i-1})$$ By using the average log probability (dividing by the completion length $K$), we normalize the scores, preventing the model from bias towards shorter completions due to cumulative probabilities.

4. What happens if we do not mask the context tokens?

If you do not mask out the context tokens (i.e. computing the average log-likelihood over the entire sequence including the prompt):

  • The score will be dominated by the model's predictions on the prompt tokens (which are already provided as inputs).
  • Because the prompt context is identical across all four completion options, including it will dilute the scoring differences between the options.
  • This makes the evaluation less sensitive to the quality of the completions, degrading the accuracy of the benchmark.
