13. Failure Gallery: Debugging & Troubleshooting

The Token's Journey

During neural network execution, a single incorrect matrix operation, scale factor omission, or datatype overflow will corrupt token representations, propagating errors that lead to system crashes or training collapse. This gallery maps the most common training bugs to their diagnostics and code solutions.

Backend Engineer Lens: Crash Logs

Debugging neural network training collapse maps directly to **interpreting server crash logs and troubleshooting database leaks**.

  • NaN Loss → Silent segmentation faults / divide-by-zero: A NaN (Not a Number) value is a silent database corruption. It usually originates from dividing by zero in softmax or floating-point overflow, propagating to corrupt every subsequent weight record.
  • Exploding Gradients → Stack overflow: Occurs when feedback adjustments compound across deep recursive calls, causing gradient numbers to grow exponentially until they exceed memory buffers, crashing the optimizer. We prevent this by setting a rate-limit guard (gradient clipping).
  • Causal Mask Leakage → Read Uncommitted Data isolation breach: If the attention layer neglects to mask future tokens, it creates a data isolation leak. The model queries data that hasn't been officially committed to the timeline yet. It achieves 0 training error by copying target values directly, but crashes during production serving where future data is unavailable.

Production Relevance

  • NaN Auditing: When training large models (e.g. 70B), a NaN loss step is extremely expensive, costing thousands of dollars in wasted compute time. Production monitoring systems (like Weights & Biases or TensorBoard) alert engineers immediately on NaN spikes. We keep multiple rolling checkpoints in our model registry so we can roll back and resume training from a healthy state after adjusting hyperparameter bounds.
  • Deterministic Seeds: During debugging, we enforce deterministic seed settings across all libraries (PyTorch, NumPy, MPS, CUDA) to reproduce the exact step where a crash occurred: 
    torch.manual_seed(42)  # guarantees identical initialization

Common Interview Followups

If your training loss suddenly becomes NaN at step 100, what are the first three troubleshooting steps you should take?

  1. Check gradient norm values: If the gradient norm is spiking before NaN, apply or tighten gradient clipping (e.g., reduce clip threshold from 1.0 to 0.5) to prevent optimization steps from overshooting.
  2. Audit FP16 precision: FP16 has a maximum value of 65,504. If weight values exceed this, they overflow to NaN. Switch to **BF16** or FP32, or add a gradient scaler (GradScaler) to scale loss down before backward passes.
  3. Reduce learning rate: A learning rate that is too high can cause parameters to step into divergent mathematical spaces, causing logits to overflow. Reduce the learning rate by a factor of 2 or 10.

What is Causal Mask Leakage? What symptom does it produce in validation metrics?

Causal Mask Leakage occurs when the causal mask in the attention layer is missing or configured incorrectly, allowing tokens to attend to future tokens in the sequence. Because the target tokens in training are simply the input sequence shifted right by 1, a model with mask leakage can simply copy the target token from its immediate right neighbor. This produces a **near-zero training loss** almost immediately. However, during validation or inference where future tokens are not visible, the model fails completely, yielding high validation loss and generating repetitive, incoherent text.
